## 配色与液态玻璃

界面是 iOS 26 的**液态玻璃**：浮动药丸顶栏、白面板、浮在内容之上的玻璃标签栏。配色为底色 `#E7F8FD`（浅冰蓝）、主色 `#1246FF`（蓝）、强调色 `#FFCC14`（黄）。

## 让磨砂真的看得见

背景是纯平的 `#E7F8FD`——没有渐变，也没有彩色底层。

这引出一条物理事实：**`blur()` 在纯色背景上什么都不会发生**。毛玻璃"看起来毛"的前提是背后有细密的东西可糊；背景一平，玻璃就退化成一块半透明白板。所以做了两件事：

**一、给背景铺一层极细的单色点阵**（14px 间距、1px 蓝点，内联 SVG，**不含任何渐变**）。它是玻璃的"毛面基底"：有玻璃的地方点被抹平，没玻璃的地方点清晰——两块区域的纹理状态一对比，磨砂感就出来了。实测这是唯一有效的办法。

**二、让 `backdrop-filter` 用上 `saturate` / `brightness`。** 这两个滤镜和 `blur` 不同，它们**在纯色上依然起作用**：`#E7F8FD` 经 `saturate(190%) brightness(1.05)` 变成 `#E6FFFF`，玻璃因此比周围更饱和、更亮一点。

至于模糊本身，仍然只在**浮动标签栏下方**能直接看到——那里有日志滚过去。

另外这个底色太亮，**明度差分不了层**：`#E7F8FD` 亮度 0.912，白面板叠上去只有 **1.07:1**。面板边界靠另外三样：

| 手段 | 取值 | 为什么 |
| --- | --- | --- |
| 白填充压低 | `.52 ~ .60` | 让上面那层"饱和 + 提亮"透得出来；填高了会把滤镜效果盖掉 |
| 1px 细描边 | `rgba(22, 32, 63, .09)` | 明度差不够，靠这圈暗描边把面板切出来 |
| 柔投影 | 两级 `--shadow` / `--shadow-lg` | 近距离描边 + 远距离柔光 |

同一个原因决定了**激活标签必须上实色**：白色药丸和标签栏只差 1.10:1，凸不出来；改成实色蓝 + 白字（6.3:1）才读得出来。

关键约束：**从不在玻璃上再叠玻璃**。激活标签和主按钮都是实色填充——颜色必须落在实色层上。

文字对比度不受影响：面板合成色 `#F3FFFF`，墨蓝 / 次级 / 三级 / 蓝分别是 **15.7 / 9.9 / 7.6 / 6.1**，四档全过 AA。

## 几处"像 iOS"的实处

- **连续圆角（squircle）**。iOS 的圆角不是正圆弧，是连续曲率。正圆弧在"直边转弧"那一刻曲率突变，看起来比 iOS 硬。用 `corner-shape: squircle`——本机 Chrome 实测支持，computed 值为 `superellipse(2)`；不支持的浏览器忽略这一条，退回普通圆角。
- **标签栏与分段控件是"一个药丸滑过去"**，不是给选中项单独染色。滑块是 `::before` + `translateX`，靠 `:has()` 驱动，只走合成器不触发重排。前提是**每格等宽**（`grid-template-columns: repeat(4, 1fr)`），否则百分比位移对不上位置。
- **图标**用 SF Symbols 风格的细描边 SVG（`stroke-width: 1.7`、圆头圆角、`currentColor` 跟随文字色），进了标签栏、主按钮、投放区和下载链接。注意 `app.js` 会覆盖 `#download` 的 `innerHTML`，所以那个图标写在 JS 模板里。
- **玻璃是四层阴影**：顶棱镜面高光 → 底棱内阴影（厚度）→ 外廓细描边 → 顶部内辉光。只留单层 inset 会像一片塑料。

## 两个只有靠测量才会暴露的坑

**1. `margin` 塌陷让页面凭空多出滚动条。** `.topbar` 的 `margin-top` 会穿透没有 padding / border 的 `body` 塌陷出去，把 100% 高度的 body 整体下推，文档高度变成 `--topbar-top + 100vh`。实测增量恰好等于 `--topbar-top`（672→678、804→811、904→912）。**元素位置完全不受影响，所以截图逐字节相同、根本看不出来**，只有量 `documentElement.scrollHeight` 才会发现。修法是 `body { display: flow-root }` 建立 BFC。

**2. 矮屏紧凑档那一组值是逐像素调出来的，别凭手感重写。** 基线留白下左栏会溢出 8px，必须压到 `gap: 9px` / `card__body: 8px 12px 9px` / `field: 5px` 才放得下。我在一次整文件重写时把它写松了，回归潜伏了三轮，直到这次复测才抓到——**改动紧凑档后必须重跑 fit 探针**。

## 另外两条颜色约束

1. **黄色不能拿来写字。** `#FFCC14` 在 `#E7F8FD` 底上只有 **1.38:1**（两者几乎同亮度），叠在面板上也只 1.48:1。黄底上要压 `#16203F` 墨蓝（10.6:1）；正文和标题用 `#1246FF`（5.8:1）或墨蓝（14.7:1）。实测墨蓝 / 次级 / 三级 / 蓝在各表面上分别是 14.7 / 9.2 / 7.1 / 5.8，四档全部过 AA。
2. **黄色的面积越大，颜色要越淡。** 纯黄只给按钮、印章、序号这类小色块；成片区域用淡黄。反过来做——比如整条标签栏平涂纯黄——会像一道荧光笔划痕，很廉价。

## 字体分三层

这是"像 iOS"最要紧的一条：自定义字体再好看，也没有系统字体那套光学尺寸、字距表和易读性调校。

| 层 | 字体 | 用在哪 |
|---|---|---|
| 正文 / 标签 / 数值 | `system-ui` → macOS 上是 **SF Pro + 苹方**（Windows 是 Segoe UI + 微软雅黑） | 表单标签、输入值、状态、说明文字、日志正文、markdown 正文 |
| 标题 / 按钮 / 展示数字 | **站酷高端黑**（`src/webui/fonts/ZhanKuGaoDuanHeiTi.ttf`，随包分发，免费商用） | 品牌字标、卡片标题、标签页、按钮、空状态标题、`## 章节标题`、印章数字 |
| 代码 / 文件名 / 格式名 | `ui-monospace` → Apple 平台是 SF Mono | markdown 行内代码、下载文件名、格式列表 |

站酷**只有一个字重**，所以有两条必须守住：`@font-face` 里声明全区间（`font-weight: 100 900`），否则浏览器会合成一个更丑的假粗体；且只出现在大字号短文本上——重型字体压在小字号正文上会喘不过气（长文档尤其，现在 `SKILL.md` 走系统字体就没这个问题了）。

**回退链必须自带中文字体。** 每一层栈里都显式写了 `"PingFang SC"` / `"Microsoft YaHei"`：Consolas 这类纯拉丁字体没有汉字，一旦让中文落到这条栈上，浏览器会**逐字回退**，同一行里混出两种字形——看起来就像"字体不全"。这是改版时踩过的坑。

数值原先用 Consolas，目的是对齐位数。其实系统字体自带这个能力，`font-variant-numeric: tabular-nums` 就够了（样式里的 `.num` 类），而 SF Pro 的表格数字正是 iOS 列表的标准做法。

## 布局：一屏放下

布局按**一屏放下**设计：顶栏高度和页面留白绑定视口高度（`clamp(…vh…)`），矮屏自动收紧，另有 `max-height: 840px` 一档兜底。实测 1366×648 及以上，左栏三张卡片和主按钮都在首屏内，页面本身不出滚动条；只有 SKILL.md 这类长文档会在内容区内部滚动。窗口更矮时由左栏内部滚动兜底。

**但"一屏放下"只在空状态成立。** 拖入文件后，进料卡里会展开诊断面板（4 行键值 + 说话人 + 5 行命中条形图，约 350px），左栏需要内部滚动约 270px 才能看到「配置」和「执行」。这是诊断面板本身的体量，不是布局错误——诊断步骤本来就是"看一眼再往下走"。

左栏用定高（而不是 `max-height`）把视口余量按 `0.35 : 1` 分给「进料」和「配置」两张卡——投放区长成真正的投放区、表单行距变宽，而不是在底部留一个空洞。收缩因子为 0，窗口变矮时卡片保持自然高度，交给滚动兜底。

## 只截空状态会漏掉什么

进料卡的 `.card__body` 曾经是 `display: flex`（默认横排）。空状态时里面只有投放区一个子元素，横排照样铺满，**截图完全正常**；一旦解析出诊断面板，两个子元素就在横排里抢宽度——投放区被压成一条窄柱，中文每行只排一个字。修法是 `flex-direction: column` + 投放区 `flex: 1 0 auto`（可长不可缩）。

**教训：这个界面有"空状态 / 已进料 / 已跑完 / 校验有问题"四种形态，只验证空状态等于没验证。** 复现"已进料"状态只需把 `#diagnosis` 的 `hidden` 去掉并填上结构一致的假数据。

## 动效

动效参考 Apple WWDC《Designing Fluid Interfaces》的思路（本机 skill 名为 `apple-design`）：

- **默认临界阻尼弹簧，不超调。** 用 CSS `linear()` 精确采样 `x(t) = 1 − (1+ωt)·e^(−ωt)`，不引第三方动画库。超调只留给"手势本身带惯性"的场景，而这个界面没有任何拖拽手势，所以一处都不用——校验印章原本那个带超调的 `cubic-bezier(…, 1.3, …)` 就是按这条换掉的。
- **按压反馈落在 `:active`。** 也就是 pointer-down 的同一帧，不等 `click`；进入用 90ms，松手回弹才交给弹簧（弹簧起步慢，按下去会发黏）。
- **字距随字号变。** 26px 的标题用 `-0.015em`，11px 的字段标签用 `+0.03em`，正文接近 0——固定一个字距值总有一处是错的。行高与字号反向：大标题 1.2，正文 1.65，日志 1.75。
- 支持 `prefers-reduced-motion`（位移/弹簧换成短透明度过渡，而不是把动效全关掉）、`prefers-reduced-transparency`（毛玻璃换实底）、`prefers-contrast: more`（去投影、改描边）。

已知取舍：字号写的是绝对 px，**不跟随浏览器的默认字号设置**。这与"一屏放下"直接冲突——用户放大字号就会撑破固定高度的视口。要改成 `rem` 的话，左栏就得接受滚动。
